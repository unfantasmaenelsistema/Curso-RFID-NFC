1. Mapa de Memoria de MIFARE Classic 1K / 4K

Una tarjeta MIFARE Classic 1K contiene 1024 bytes de memoria EEPROM estructurados en 16 sectores independientes (Sectores 0 a 15). Cada sector cuenta con 4 bloques de 16 bytes (64 bloques en total, numerados del 0 al 63).

1.1 Anatomía del Bloque de Valor (Value Block)

Para aplicaciones de monedero electrónico (cafeterías, lavanderías, máquinas de vending), MIFARE define una estructura especial con detección de errores y operaciones atómicas de INCREMENT, DECREMENT y RESTORE:

┌────────────────────────────────────────────────────────────────────────────────────────┐ │ ESTRUCTURA DE UN VALUE BLOCK (16 BYTES) │ ├────────────────────────────────────────────────────────────────────────────────────────┤ │ Bytes 0-3: Valor con signo en complemento a 2 (Little Endian): [ v ] │ │ Bytes 4-7: Inversión bit a bit del valor (NOT bitwise): [ ~v ] │ │ Bytes 8-11: Copia exacta de respaldo del valor: [ v ] │ │ Byte 12: Dirección del bloque de almacenamiento: [ adr ] │ │ Byte 13: Inversión bit a bit de la dirección: [ ~adr ] │ │ Byte 14: Copia de la dirección: [ adr ] │ │ Byte 15: Inversión bit a bit de la dirección: [ ~adr ] │ │ │ │ Ejemplo para un saldo de 25.00 € (2500 céntimos = 0x000009C4) en bloque 4: │ │ v = C4 09 00 00 │ │ ~v = 3B F6 FF FF │ │ adr = 04 FB 04 FB │ │ Bloque 4 = C4 09 00 00 3B F6 FF FF C4 09 00 00 04 FB 04 FB │ └────────────────────────────────────────────────────────────────────────────────────────┘

1.2 Decodificación de los Access Bits (Bytes 6, 7 y 8 del Trailer)

Los 3 bits de control C1, C2, C3 determinan si los bloques de datos y el propio sector trailer pueden leerse o escribirse con la Key A o la Key B. Por diseño de seguridad de NXP, la Key A nunca puede leerse: si se lee el Sector Trailer, el lector siempre recibirá ceros (00 00 00 00 00 00) en los primeros 6 bytes.

3. Ataque Darkside (Courtois 2009) y PRNG Débil

¿Qué ocurre si la tarjeta tiene todas las claves cambiadas y desconocidas? En 2009, el criptógrafo Nicolas T. Courtois descubrió el ataque Darkside.

Cuando un lector envía una clave errónea en una autenticación MIFARE, la tarjeta responde con un código NACK cifrado de 4 bits. Sin embargo, debido a un fallo de diseño en la función de paridad del algoritmo Crypto-1, el bit de paridad se calcula antes de cifrar. Al enviar miles de consultas con tiempos de reloj cuidadosamente calculados, la tarjeta filtra bits del estado interno del generador pseudoaleatorio (LFSR de 48 bits), permitiendo resolver la primera clave secreta en menos de 3 minutos.

🎯 Objetivos de Aprendizaje

  • Comprender la debilidad del generador de números pseudoaleatorios (PRNG) de NXP.
  • Ejecutar el ataque Darkside para extraer el primer vector de autenticación.
  • Aprender por qué las tarjetas modernas con "Hardened PRNG" resisten el Darkside.

🔑 Conceptos Clave

4. Ataques Nested y Hardnested

Una vez recuperada al menos una clave válida (mediante diccionario o Darkside), el ataque Nested aprovecha que el PRNG de MIFARE Classic no es verdaderamente aleatorio, sino una función determinista basada en el tiempo transcurrido desde el reset ($n_T$). Al autenticarse en el sector conocido y solicitar una segunda autenticación en el sector objetivo, la distancia temporal entre nonces revela la clave en milisegundos.

🎯 Objetivos de Aprendizaje

  • Entender el ataque Nested clásico para tarjetas con PRNG predecible.
  • Ejecutar el ataque Hardnested (Carlo Meijer 2015) para tarjetas con PRNG parcheado.
  • Acelerar el crackeo mediante tablas precomputadas o GPU.
